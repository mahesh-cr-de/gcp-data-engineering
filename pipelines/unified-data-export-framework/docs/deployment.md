# Deployment and scheduling

Run commands from `unified-data-export-framework/`. Replace uppercase values.

## Enable APIs and create identities

```bash
gcloud services enable cloudfunctions.googleapis.com cloudbuild.googleapis.com \
  run.googleapis.com artifactregistry.googleapis.com bigquery.googleapis.com \
  bigquerystorage.googleapis.com storage.googleapis.com \
  secretmanager.googleapis.com cloudscheduler.googleapis.com

gcloud iam service-accounts create unified-export-runtime \
  --display-name="Unified export runtime"
gcloud iam service-accounts create unified-export-scheduler \
  --display-name="Unified export scheduler"

PROJECT_ID="$(gcloud config get-value project)"
RUNTIME_SA="unified-export-runtime@${PROJECT_ID}.iam.gserviceaccount.com"
SCHEDULER_SA="unified-export-scheduler@${PROJECT_ID}.iam.gserviceaccount.com"
```

Grant `roles/bigquery.jobUser` on the query project and
`roles/bigquery.dataViewer` on only the source datasets. Grant
`roles/storage.objectAdmin` on only the export bucket and
`roles/secretmanager.secretAccessor` on each credential secret. Organization
policy may require custom roles with a narrower permission set.

```bash
printf '%s' 'REPLACE_WITH_PASSWORD' | \
  gcloud secrets create vendor1-sftp-password --data-file=-

gcloud secrets add-iam-policy-binding vendor1-sftp-password \
  --member="serviceAccount:${RUNTIME_SA}" \
  --role="roles/secretmanager.secretAccessor"
```

## Deploy Gen2 with Python 3.12

Set the function timeout slightly above the largest permitted request timeout;
the application reserves cleanup time. Concurrency is one because each request
owns a potentially large local artifact.

```bash
gcloud functions deploy unified-data-export \
  --gen2 \
  --runtime=python312 \
  --region=us-central1 \
  --source=. \
  --entry-point=unified_data_export \
  --trigger-http \
  --no-allow-unauthenticated \
  --service-account="${RUNTIME_SA}" \
  --memory=4Gi \
  --cpu=2 \
  --concurrency=1 \
  --timeout=1800s \
  --max-instances=10 \
  --set-env-vars="MAX_REQUEST_TIMEOUT=1700,MAX_TEMP_FILE_BYTES=3221225472,BQ_STORAGE_MAX_STREAMS=1,LOG_LEVEL=INFO"
```

For a private SFTP endpoint, attach a Serverless VPC Access connector and use
`--vpc-connector=CONNECTOR --egress-settings=private-ranges-only`. Confirm DNS,
routes, firewall egress, and TCP/22 reachability from that connector.

## Grant authenticated invocation

```bash
gcloud functions add-invoker-policy-binding unified-data-export \
  --gen2 \
  --region=us-central1 \
  --member="serviceAccount:${SCHEDULER_SA}"

FUNCTION_URL="$(gcloud functions describe unified-data-export \
  --gen2 --region=us-central1 --format='value(serviceConfig.uri)')"
```

## Create the Scheduler job

Put the request in `scheduler-body.json`. Scheduler sends it unchanged; the
function, not Scheduler, renders date placeholders.

```bash
gcloud scheduler jobs create http vendor-sales-daily \
  --location=us-central1 \
  --schedule="0 6 * * *" \
  --time-zone="Asia/Kolkata" \
  --uri="${FUNCTION_URL}" \
  --http-method=POST \
  --headers="Content-Type=application/json" \
  --message-body-from-file=scheduler-body.json \
  --oidc-service-account-email="${SCHEDULER_SA}" \
  --oidc-token-audience="${FUNCTION_URL}" \
  --attempt-deadline=1800s \
  --max-retry-attempts=3 \
  --min-backoff=30s \
  --max-backoff=300s
```

Use a business-date-specific `idempotency_key`. Scheduler bodies are static, so
explicit daily keys are easiest when definitions are generated by Terraform or
CI/CD; otherwise the derived key includes the filename template.

## Environment variables

| Variable | Default | Purpose |
|---|---:|---|
| `GOOGLE_CLOUD_PROJECT` | runtime project | fallback query/secret project |
| `MAX_REQUEST_TIMEOUT` | `3500` | upper bound accepted from callers |
| `MAX_TEMP_FILE_BYTES` | `4294967296` | abort threshold for local artifact |
| `BQ_STORAGE_MAX_STREAMS` | `1` | result read parallelism |
| `LOG_LEVEL` | `INFO` | structured log threshold |
| `ALLOW_INLINE_SFTP_PASSWORD` | `false` | emergency compatibility control |
| `SFTP_HOST_KEY` | unset | deployment-wide known-host line fallback |

Keep `ALLOW_INLINE_SFTP_PASSWORD=false` in production.
